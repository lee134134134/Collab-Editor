# 文档规范

## 注释

- 注释解释「为什么」，不解释「做什么」。
- 导出函数/类型用 JSDoc 简述职责、参数与副作用。
- 复杂协同逻辑（房间生命周期、快照落库、ticket 重连）必须写清楚约束与竞态处理。
- 中文注释使用半角冒号 + 空格。

## 文档同步

- 项目命令、目录、端口、环境变量变更 → 同步 `AGENTS.md`、`CLAUDE.md`、`README.md`。
- shared 契约变更 → 同步 `packages/shared/src/index.ts` 与相关 API 文档/注释。
- 新增页面/路由 → 同步 `config/routes.ts` 与 locale 菜单文案。
- 新增测试命令 → 同步 `AGENTS.md` 命令表与 `package.json` scripts。

## 不应做的事

- 不在 `references/` submodule 内写本项目文档。
- 不复制两份规范；`AGENTS.md` 是主文档，`CLAUDE.md` 只做摘要并指向它。
- 不提交与代码不符的“计划文档”；未实现能力放“已知限制”。

## 提交信息

- Conventional Commits，中文描述：
  - `feat: 新增评论线程回复`
  - `fix: 修复 ticket 过期后重连失败`
  - `refactor: 归并 shared 协同类型`
  - `docs: 更新运行命令`
  - `test: 补文件锁单测`
- 一个提交只做一件事；不混入无关格式化。
