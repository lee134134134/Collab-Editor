# 路由规范（NON-NEGOTIABLE）

## 路由注册

- 唯一路由表：`apps/web/config/routes.ts`。
- 页面组件按约定放 `src/pages/`；Umi 通过 `component: './docs'` 自动解析。
- 动态路由用 `:id`（如 `/docs/:id`），编辑器页设置 `hideInMenu: true`。

## 当前路由结构

```ts
/user/login          # 登录（layout: false）
/docs                # 文档库（默认首页）
/docs/:id            # 编辑器（hideInMenu）
/                    # redirect → /docs
*                    # 404
```

## 登录守卫

- 守卫在 `app.tsx` 的 `layout.onPageChange`：
  无 `initialState.currentUser` 且不在 `/user/login` → 跳登录并带 `redirect`。
- 登录成功后由 `getInitialState` / `getMe` 恢复用户态；token 存 localStorage。
- 新增受保护页面无需额外配置，只要不在登录页路径即可。
- 新增公开页面时需在守卫逻辑中显式放行，不能靠“没有 initialState”绕过。

## 菜单

- 菜单由 Umi layout 根据路由 `name` + `src/locales/zh-CN/menu.ts` 生成。
- 需要出现在侧边栏的路由：设置 `name`、`icon`，并在 locale 增加 `menu.<name>`。
- 不需要菜单：`hideInMenu: true`。
- 修改路由后同步检查 `menu.docs` / `menu.docs.editor` 文案。

## 新页面检查清单

- [ ] `config/routes.ts` 已注册，组件路径存在
- [ ] 需要菜单时已加 `name`、`icon`、locale 文案
- [ ] 受保护页面确认守卫行为
- [ ] `pnpm type-check` 通过
