# 编码规范

## TypeScript（NON-NEGOTIABLE）

- strict 模式；禁止 `any` / `@ts-ignore` 压制错误。需要宽松类型时用 `unknown` 并收窄。
- 类型导入用 `import type`；前后端共享契约优先引用 `@collab/shared`。
- 保持 `noUnusedLocals` / `noUnusedParameters` 通过，不留未使用导入/变量。
- API 返回类型必须显式声明；Umi request 调用使用泛型。
- 服务端使用 NodeNext ESM，相对导入带 `.js` 后缀（如 `./config.js`）。

## 命名

| 类型 | 规则 | 示例 |
|---|---|---|
| 前端页面/组件文件 | PascalCase | `CommentPanel.tsx` |
| hooks | `use` + PascalCase | `useCollabDoc` |
| 服务/工具文件 | camelCase | `requestErrorConfig.ts` |
| 变量/函数 | camelCase | `handleCreateComment` |
| 常量 | UPPER_SNAKE_CASE | `WS_MSG_COMMENT_ACTIVITY` |
| 接口/类型 | PascalCase | `CommentDTO`、`PresenceUser` |
| CSS 类名 | BEM | `doc-editor__header` |
| 数据库字段 | snake_case | `parent_id`、`created_at` |

## 注释与语言

- 注释、UI 文案、提交信息用中文；标识符用英文。
- 注释解释「为什么」，不解释「做什么」；导出 API 用 JSDoc。
- 中文注释使用半角冒号 + 空格：`// 说明: ...`。

## 导入顺序

1. 第三方库（React、antd、Umi、Tiptap、Yjs）
2. `@collab/shared`
3. 项目内部 `@/`
4. 类型导入（`import type`）
5. 副作用导入（CSS）

前端内部导入一律用 `@/`（指向 `apps/web/src`），禁止深层相对路径；同目录模块可用 `./`。
