# 测试规范

## 质量门禁（NON-NEGOTIABLE）

每次改动至少执行：

```bash
pnpm type-check      # 全仓类型检查
pnpm lint            # Biome
```

涉及协同 / REST / 数据库时补：

```bash
pnpm test            # 服务端 Vitest（collab + file-lock）
pnpm test:integration # 需后端已启动：REST + 双客户端 Yjs 收敛 + 评论
pnpm test:e2e        # 浏览器 E2E（需 Chrome；可自动拉起服务）
```

## 测试分层

| 层 | 位置 | 覆盖 |
|---|---|---|
| 单测 | `apps/server/test/*.test.ts` | 房间/快照/文件锁等纯逻辑 |
| 集成 | `apps/server/test/integration.mjs` | 登录、文档、ticket、双端收敛、评论 CRUD |
| 浏览器 E2E | `scripts/e2e.mjs` | 登录、新建文档、双用户实时输入、在线头像、刷新持久化 |

## 编写要求

- 新逻辑优先补单测；协同/协议改动必须跑集成测试。
- 测试不得依赖仓库内 `data/collab.db` / `collab.lock`；用临时目录或独立测试库。
- E2E 清理创建的文档，避免污染开发库。
- 测试失败先定位根因，不要用放宽断言/跳过用例掩盖。
- 前端暂未引入组件单测；新增复杂 hook 时可先用 Vitest + jsdom，需同步门禁命令。
