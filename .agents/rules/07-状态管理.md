# 状态管理（NON-NEGOTIABLE）

## 技术选型

- 前端不引入 Redux / Zustand / MobX / Pinia。
- 全局登录态用 Umi `@@initialState`（`app.tsx` 的 `getInitialState` + `useModel`）。
- 组件内状态用 `useState` / `useRef`；派生值用 `useMemo`。
- 协同文档状态以 **Yjs `Y.Doc` 为唯一权威**，React 状态只做 UI 镜像；不要另存一份文档内容。

## 状态归属

| 状态类型 | 放哪 | 示例 |
|---|---|---|
| 登录用户 / 全局设置 | `@@initialState` | `currentUser`、布局 settings |
| 组件 UI 状态 | `useState` | 弹窗开关、输入框、loading |
| 路由参数 | `useParams` / `useSearchParams` | `docId` |
| 协同内容 / 评论 Mark | `Y.Doc` / Y.Text / Y.Map | 正文、评论锚点 |
| 在线用户 | y-websocket `awareness` | PresenceBar |
| token | `localStorage` | 仅 `app.tsx` 与登录页读写 |

## Yjs 生命周期

- `Y.Doc` + `WebsocketProvider` 在 `useCollabDoc` 内创建，卸载时 `destroy()`。
- 连接状态由 hook 的 `status` 暴露；`4401` 换 ticket 重建，指数退避 1s→10s；重建以服务端快照恢复，断线期间的未同步修改可能丢失。
- 不要在多个组件重复创建 provider；通过 props 传递或自定义事件通信。
- 评论活动用 `window` 自定义事件 `collab:comment-activity` 广播，避免把事件塞进全局 store。

## 约束

- 禁止在组件外直接修改 `initialState`；通过 `setInitialState`。
- 禁止把协同正文复制到 React state 再双向同步（会与 CRDT 冲突）。
- token 读写集中在登录页与 `app.tsx`；其他模块通过请求拦截器隐式使用。
